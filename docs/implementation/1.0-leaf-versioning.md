# 1.0 leaf versioning

Policy for first-party package versions at the 1.0 freeze. This file
does not split the workspace. Crate, wheel, and npm version fields are
lockstep unpublished `1.0.0`.

Preview feedback
([`preview-feedback-review.md`](preview-feedback-review.md)) found no
lockstep coupling harm. Independent first-party versioning is therefore
**not** started here.

## Core (lockstep through `1.0.0`)

These packages share one version and one compatibility promise:

- `finstack-ai-kernel`
- `finstack-ai-runtime`
- `finstack-ai`
- `finstack-ai-protocol`
- `finstack-ai-test`
- Python (`finstack-ai`) and JS/WASM (`@finstack/ai`) bindings

A breaking change in any core package is a framework major.

## First-party leaves

Providers, tools, stores, observers, workflow, and plugin-host **may**
take independent versions after GA only when both are true:

1. A preview-feedback review names a coupling problem; and
2. The leaf publishes an engine-compatibility range (for example
   `engine = ">=1.0.0, <2.0.0"`).

Default in this freeze: keep lockstep. Do not invent per-leaf versions.

WIT package names are not crate versions. `@0.0.4` remains the
experimental guest line; `@1.0.0` is the frozen world line. Both load
through explicit host adapters. See
[`1.0-compatibility-policy.md`](1.0-compatibility-policy.md).

## Third-party packages

Third-party extensions were already independently versioned. They must
not be treated as lockstep core.

## Experimental leaves

IndexedDB, `@0.x` WIT after freeze, and process session vocabulary (if
still later) stay experimental. They do not receive a permanent engine
range in this file.
