PASS  T2/T5 boundary and SEC-INV-001
      Pydantic callbacks remain explicitly trusted in-process application code.
      Schemas, model arguments, and model results remain data and grant no
      authority. Tool policy/approval and resolved call identity remain Rust
      runtime inputs; the decorator cannot bypass them.

PASS  SEC-INV-002 and commit-before-effect ordering
      Structured output is configured with a committed ConfigureOutput input.
      Validation is submitted as OutputValidated. Retryable invalid output is
      committed as RetryScheduled plus a timer effect before the timer driver
      executes. Pydantic never calls the kernel or executes a runtime effect.

PASS  TM-02 and tool/result association
      Invalid model arguments are rejected by the existing precompiled Rust
      input validator before Python entry. Decorated results are serialized
      once and passed through the existing output validator, preserving
      tool_arguments_invalid/tool_output_invalid and source-call association.

PASS  TM-06 and Python trust labeling
      Documentation states that callbacks inherit process memory and authority.
      The optional adapter adds no sandbox/isolation claim, lock-held callback,
      per-token callback, or dynamic extension loading.

PASS  TM-16 and SEC-INV-007
      The portable normalizer rejects non-object schema nodes, traversals deeper
      than 64, more than 64 anyOf branches, open objects, optional provider
      properties, array-valued type, unknown keywords, external references, and
      unsupported drafts. The canonical Rust parser/validator retains existing
      raw JSON and validation-issue bounds. Output retries are capped by both
      run configuration and immutable accepted RunLimits.

PASS  SEC-INV-004/009/010
      Existing kernel duplicate/conflict, terminal immutability, strict replay,
      state-hash, and retry transition rules remain unchanged. Output validation
      uses the frozen SchemaRef digest and exact terminal candidate identity.

PASS  SEC-INV-005/011
      Registration errors expose only schema keyword and JSON pointer, not raw
      model/tool values. Pydantic exceptions from trusted tool result conversion
      are not forwarded into durable errors; Rust emits the stable output code.
      Aggregate secret scan and canary pass.

PASS  SEC-INV-012 and TM-18
      Pydantic is an optional wheel extra and is absent from the Rust/default
      dependency graph. Top-level import does not import it. Pinned test tooling,
      supply-chain policy, source distribution, installed-wheel tests, and
      reproducible staging pass.

Residual conditions:
  - Pydantic callbacks are trusted T2 code; applications must isolate untrusted
    extensions through the later WIT/Wasmtime host.
  - The initial portable subset is deliberately narrower than full Draft 2020-12
    and provider-specific translation remains later scope.
  - PR-063 still owns final 1.0 memory/performance budget ratification.

No independent review, external approval, live-provider test, publication,
browser/WASM binding claim, or G4 approval is recorded here.
