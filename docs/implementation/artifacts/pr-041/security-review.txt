defaulted JournalStore method, not a seventh port.

PASS  TM-13 / snapshots never authoritative
      Envelope v1 is protocol-owned canonical CBOR over existing
      KernelState. Fields include format_version, sequence,
      head_checksum, state_hash, pending_timer_scheduled_at, and
      state. OpaqueSnapshot.bytes are that CBOR; the cache digest is
      Digest::snapshot_state(bytes) under DOMAIN_SNAPSHOT_STATE /
      schema 1. Kernel::try_restore only hydrates after validate and
      state_hash. recover tries accelerated restore, then full replay.
      Load/recover never fail because of a bad snapshot when the
      journal is intact. last_snapshot_sequence is seeded only when
      accelerated restore succeeded. SnapshotWritten is not emitted
      from decide or the scheduler. Host/proxy stores leave
      accelerated = None. No sqlite DDL change.

PASS  TM-12 / journal remains the recovery source
      A01 deletes the snapshot cache and recovers the same state_hash
      from records. A02 keeps load successful for corrupt, digest-
      mismatched, unknown-version, and forked-checksum snapshots.
      Recover also discards a snapshot that is ahead of head, whose
      sequence/state_hash/journal checksum disagree, that straddles a
      batch, or whose tail apply fails. v1 acceleration is prefix-
      apply skip; load() still returns the full session.

PASS  TM-16 / bounded snapshot decode
      Store snapshot_bytes ceilings still wrap OpaqueSnapshot::try_new.
      Protocol decode uses the existing canonical CBOR limits.
      Scheduling default is every_n_records=32 and write_timeout=50ms.
      every_n_records==0 disables writes. Timeout, unsupported, and
      write errors never fail the run. native-tokio bounds the write
      with tokio::time::timeout. wasm-host has no timer; HostJournalStore
      stays unsupported. RawJson human JSON still rejects duplicate
      keys and source-span overflow; CBOR continues to carry JCS bytes.

Residual already recorded:
  Checksums and state_hash detect accidental or unsynchronized
  snapshot cache edits. They do not authenticate a coordinated
  rewrite of records, snapshots, and the head together.
  At 64 records, snapshot-plus-tail restore is not faster than full
  replay; no compact-projection ADR is proposed. Compaction/prune,
  crash-prefix, IndexedDB v1, default Agent/Python/WASM sqlite
  wiring, and G5 remain later PRs.
