Control disposition

PASS - TM-17 observer failure and blockage remain non-semantic
Interactive and observer subscribers have independently owned bounded inboxes
and batch queues. Interactive BlockBounded delivery can wait only for its
configured non-zero timeout. Observer fan-out uses non-blocking admission and
never waits on the source path; saturation drops transient progress under the
configured policy or closes the observer explicitly. Subscriber filtering,
lag, receiver drop, and task closure never enter the coordinator error path or
change committed kernel state. A stalled observer is directly proven not to
delay an interactive subscriber or semantic settlement.

PASS - durable completion cannot be silently lost
DropProgress discards only transient events and accounts for every dropped
event. Durable delivery waits for its bounded timeout and otherwise closes with
the explicit MissedDurable reason; Disconnect is likewise explicit. Pending
progress flushes before durable events and terminal events flush immediately.
The missed-durable integration fixture proves that the subscriber may miss the
terminal batch while the authoritative journal still recovers RunCompleted.
No new snapshot or RunResult API is fabricated.

PASS - SEC-INV-009 terminal immutability and observer separation
The hub receives committed immutable RunEvent values after apply and before
post-commit dispatch. It has no kernel input, reducer, journal append, or port
execution authority. The internal observer route is separate from interactive
delivery and is not yet attached to a public Observer trait. Terminal records
remain immutable and observer/subscriber outcomes cannot alter execution.
ADR-009 therefore advances only to In progress / Partial; PR-018, PR-020, and
PR-057 remain required.

PASS - TM-04 and SEC-INV-005 sensitivity boundary for PR-017
Each subscription has an immutable maximum-sensitivity filter and optional
event-kind/class filters. Filtered events are not counted as lag drops. PR-017
adds no exporter, telemetry default, network path, credential reveal, logging
of event bodies, or observer projection. Metadata-only and redacted observer
views remain PR-057; full-content telemetry is not enabled by default.

PASS - TM-16 and SEC-INV-007 resource bounds
Hub source capacity, subscriber count, both per-subscriber queues, batch count,
batch serialized bytes, batch interval, lag timeouts, model driver messages,
and tool driver messages are explicitly non-zero and bounded. Serialized
RunEvent size is calculated once at ingestion. Batches flush before crossing
count/byte thresholds; one oversized event is delivered alone. Kind filters
reject duplicates, and source progress sequences must be contiguous. The
100,000-event direct test uses only configured queues and shuts down cleanly.
RunTaskOwner drains hub/subscriber tasks normally and aborts them with other
owned tasks at deadline expiry.

PASS - ordering, identity, and runtime fault boundary
The coordinator publishes committed events after journal apply and before
post-commit effect dispatch. Hub infrastructure failure faults the runtime
before newly committed work is dispatched, while subscriber-local failure does
not. Progress is materialized on arrival, receives a runtime UUIDv7 EventId
from a run-scoped entropy stream isolated from semantic ID allocation, advances
the single source sequence, and is published before terminal settlement.
Flattened multi-subscriber batches preserve exact event identity, correlation,
sequence, and order.

PASS - TM-18 and SEC-INV-012 target/dependency boundary
Tokio time-test support is dev-only. Minimal and selected wasm-host production
graphs remain Tokio-free. Architecture, Clippy, docs, conformance,
supply-chain, secret, release-smoke, and aggregate CI checks pass. No provider,
SDK, binding, exporter, network service, Observer trait, or plugin engine is
added.

  observers remain read-only.
- PR-020 owns performance baselines and the wider runtime fault/concurrency
  gate; the 100,000-event case here proves bounds, not a performance target.
- PR-057 owns metadata-only/redacted observer and telemetry projections.
- Later SDK/binding work owns ergonomic result and snapshot handles. The

- No new ADR or planning amendment trigger was found. This review passes
