Result: PASS for implemented candidate scope

Reviewed controls

- TM-18: PyO3 and maturin are exactly pinned; the PEP 517 build dependency is
  hash-constrained; Cargo.lock is required; workflow actions are full-SHA
  pinned; cargo-deny, actionlint, archive inspection, exact hashes, secret scan,
  and the secret-scan canary pass.
- Reproducible uv/Maturin builds set `MATURIN_NO_INSTALL_RUST=1`. The checked-in
  Rust toolchain is mandatory, so a missing Cargo executable fails closed
  instead of adding Maturin's conditional network bootstrap dependency.
- Hosted CI resolves and exports an explicit Python interpreter before PyO3
  compilation, and coverage installs the mixed project before importing it;
  neither check can silently substitute a source-only facade.
- The Python composition alone enables the provider's narrowly forwarded
  vendored-native-TLS feature so portable Linux wheels do not depend on an
  undeclared system OpenSSL. The provider's accepted default native-TLS policy
  is unchanged, and the added `openssl-src` lock entry passes cargo-deny.
- SEC-INV-005 / TM-04: import and `health()` are credential-free. A subprocess
  audit observes no Python socket events or new threads, and the Rust module
  does not create a Tokio runtime or provider client at import.
- TM-06: the native module is the approved trusted in-process binding path and
  reuses the Rust SDK/provider implementation. It does not introduce a native
  dylib plugin ABI or a second semantic engine.
- Archive safety: wheel/sdist checks reject absolute/traversal paths, links,
  private build paths, generated bytecode, missing licenses/stubs, classic
  abi3 names, duplicate artifacts, metadata drift, and oversized wheels.
- Free-threaded safety: the module declares `gil_used = false`; the dedicated
  3.14t smoke requires a disabled GIL and exercises 512 concurrent native
  `health()` calls.

Residual conditions

- A PyO3 native extension is trusted in-process code, not an OS sandbox.
- The final exact candidate passed the complete manylinux x86_64/aarch64,
  macOS arm64, and Windows x64 CPython 3.11-3.14/3.14t wheel matrix plus all
  three hosted security jobs. The retained failed attempts close no item.
- The OpenAI-compatible provider is linked but no client is created and no live
  provider or credential path is exercised.
- Deterministic SBOM/provenance staging and publication controls remain PR-032.
- Package publication and independent security review were not performed.

No exception or new ADR trigger is required. Hosted matrix completion is an
acceptance condition, not a security waiver.
