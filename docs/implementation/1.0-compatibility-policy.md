# 1.0 compatibility policy

Adopter-facing SemVer promise for the framework `1.0.0` freeze. This file
extends, and does not replace,
[`compatibility-governance.md`](compatibility-governance.md) (owners and
fixtures) or
[`preview-compatibility-policy.md`](preview-compatibility-policy.md)
(historical tagged `0.1.0` scope).

Status: **Approved** by `COMP-1.0-D-contract-freeze-00b78667ecc4`.
G8 passed via `G8-D-general-availability-a889a29a3f54`. This file is
not that decision. Workspace crate, wheel, and npm **version fields**
are `1.0.0`. Local tag `v1.0.0` exists. Do not treat this freeze as a
crates.io / PyPI / npm publication.

Planning docs under `docs/planning/` remain authoritative.

## Freeze set

Engineering Standards §6.1 families that leave experimental status:

| Family | 1.0 disposition | Unknown-field / evolution |
| --- | --- | --- |
| Public Rust API (kernel / runtime / SDK) | Frozen SemVer; breaking = major | Semantic renames and removals are major |
| Python public modules and exceptions | Frozen; wheel matrix stays ADR-018 | New exports may be additive; removals are major |
| JS/TS exports and WASM host ABI | Frozen; no SharedArrayBuffer requirement (ADR-031) | New exports may be additive; removals are major |
| AgentSpec / BundleSpec / locks | Strict reject-unknown | Additive fields need a version or default |
| Journal records / snapshots | candidate-v1 is the 1.0 durable line | Schema-declared ignorable optionals preserved; unknown state-bearing fields and kinds are fatal (TDD §28.4) |
| Runtime events (durable-derived) | Order and class frozen | Durable-derived payloads follow the durable unknown-field rule; transient progress stays non-replay-stable |
| Remote protocol | Inbound reject-unknown; version handshake | Strict inbound; negotiated outbound optionals |
| Process family | Handshake-only | Session vocabulary is later and is not frozen |
| WIT `finstack:ai-types/host/toolset/context@1.0.0` | Frozen exact worlds | Coarse completion only; unknown world or undeclared field fails closed |

Framework `0.1.0` mapped to experimental WIT package names
`finstack:ai-*@0.0.4`. After this freeze, `@1.0.0` is the permanent WIT
promise. `@0.x` guests keep loading through explicit host adapters.
Silent semantic discard remains prohibited (NFR-COMP-003).

## Experimental exclusions

These surfaces have **no** permanent 1.0 promise and must stay labeled:

- IndexedDB host journal (inspect-not-continue; not NFR-REL-001)
- WIT `@0.x` after this freeze (loadable, not the permanent world)
- Observer isolation / WIT observer worlds (needs a later ADR)
- Process-plugin session commands (do not exist; handshake-only)
- SharedArrayBuffer / cross-origin isolation (ADR-031)
- Marketplace, native dylib ABI, PostgreSQL, exactly-once delivery

A project that used only an excluded surface is outside the permanent
migration promise. See [`docs/site/migration.md`](../site/migration.md).

## ADR triggers

A change that alters journal meaning, durable event order, WIT world
shape, or remote/process protocol meaning needs an ADR, migration
analysis, and fixtures in the same change. Do not add a seventh port,
eighth middleware stage, kernel I/O, or dylib loader without the
Implementation Plan §6.3 path.

Resource-based WIT streaming and observer WIT worlds stay deferred
(ADR-035). Delivery stays at-least-once (ADR-013).

## Deprecation and removal

Every remaining `#[deprecated]` / Python warning / JS `@deprecated` on
the 1.0 surface must name `since` and a removal version (`2.0.0` or a
dated 1.x). Aliases stay until that version. New deprecations come from
reviewed preview feedback, not invention. Inventory:
[`1.0-deprecation-inventory.md`](1.0-deprecation-inventory.md).

## Leaf engine ranges

Core kernel, runtime, SDK, protocol, test, and bindings stay lockstep
through the `1.0.0` cut. First-party leaves may take independent
versions after GA only when preview feedback names coupling harm **and**
the leaf publishes an engine-compatibility range. Default:
[`1.0-leaf-versioning.md`](1.0-leaf-versioning.md) — keep lockstep; do
not split versions in this freeze.

## How breaking-change tests run

For each frozen family, `fixtures/compatibility/` holds at least one
negative that would have passed if unknown state-bearing data were
silently dropped. Wire-up:

- `cargo test -p finstack-ai-test --offline --locked --test breaking_change`
- family tests (`journal_v1`, `public_rust_api`, AgentSpec, protocol
  compat fixtures)
- `mise run check-wit` for `@1.0.0` and `@0.0.4`

Do not invent `mise run schema-governance` for this freeze. Public Rust
uses a checked-in public-item list from tagged `v0.1.0`, not a new
toolchain.
